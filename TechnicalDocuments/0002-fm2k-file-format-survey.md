# 0002: FM2K データフォーマット調査（初期）

- **日付**: 2026-09-28
- **状態**: 調査中

## ファイル署名

全ファイル先頭 16 バイト = 署名 (8B) + 予約 + フラグ。

- `2DKGT2G\0` — 本作の実データ全部（`.kgt` / `.player` / `.stage` / `.demo`）
- `2DKGT2K\0` — `new1.player`, `新2.player` のみ（219KB、未使用のテンプレート残骸と見られる）
- オフセット `0x0C` の uint32: `.kgt` と `.player` は `1`、`.stage` と `.demo` は `0`

`2DKGT2G` は「ゲーム配布用（エディタでは開けないようロックした）」版と見られる。
`.kgt` の先頭をダンプすると SJIS 文字列が平文で並んでいる → 暗号化・圧縮はされておらず、
レイアウトは `2DKGT2K` と同じ可能性が高い（未検証）。

## .kgt 先頭の観察

- `0x10` から 256B: ゲーム名 SJIS 「ヴァンガードプリンセス」
- `0x110` 以降: 「技」（スクリプト）テーブル。1 エントリに SJIS 名＋数値。
  例: 「――設定無し――」「ヒット文字 "HIT"」「ヒット数字 0..9」「ラウンド開始時アニメ」

## fm2ndparser での抽出結果（2026-09-28）

ロック判定（`BaseParser.cs:47` の `2DKGT2G` → `LockedFileException`）だけを無効にしたローカルビルドを、
`.kgt` を起点に `-x`（リソース抽出あり）で実行した。

- **全38ファイルが解析を通った**（kgt 1 / player 13 / stage 7 / demo 17）。所要時間は約10分、出力は約1.5GB。
- → `2DKGT2G` は `2DKGT2K` と同じレイアウトで、違うのはロックの印だけ、と確定。
- 未解析ブロック（`Unknown`）は、ゆいの場合で 16 / 約35,000。ほぼ全部読めている。
- キャラ画像は `<キャラ>/1`〜`8/` の 8 フォルダに分かれる。**パレット（カラー）違いの同じ絵**。1 キャラ約900枚 × 8。
- ステージ・デモの画像は `img/`、音声は `snd/`。ステージ背景は 1280x960。
- 出力は 8bpp インデックス BMP。背景色（黒）がそのまま出ているので、PNG にするときに透過の扱いを決める必要がある。
  → 透過は **純黒 RGB (0,0,0)**（0007 で訂正。「番号 0」ではない）
- 出力先: scratchpad（一時領域）。リポジトリには入れていない。

### バイナリ構造メモ（fm2ndparser のソースから）

- ヘッダ: 型名 12B + uint32 フラグ + 名前 256B → `0x110` から技テーブル
- 技: uint32 個数 + 39B × 個数（名前 32B / 開始ブロック位置 u16 / 予約 1B / 種別 u32）
- ブロック: uint32 個数 + 16B 固定長 × 個数。先頭 1B が種別（0 = Settings, 12 = I(画像), 24 = FA(攻撃判定), 25 = FD(やられ判定) など）
- 画像: uint32 個数 + (4B + 幅 u32 + 高さ u32 + パレット種別 u32 + 圧縮サイズ u32 + データ)。
  独自の RLE/LZ 系圧縮（`extractSprite`）。パレット種別 1 は先頭 1024B に専用パレットあり
- 共通パレット: 0x420B × 8。色は BGRA、A は 0/1
- 音声: uint32 個数 + (4B + 名前 32B + サイズ u32 + フラグ 1B + CDDA 1B + データ)

### I ブロック（画像表示）の座標の意味

- **(x, y) = 画像の「下端中央」を置く位置**（キャラの原点から見た相対座標）。
- 検証: ゆいの立ち・前歩きで、各コマの足元（最下段の不透明ピクセル）が
  - 下端基準なら高さのぶれ 0（左上基準だと 4〜8px、中央基準だと 2〜4px ぶれる）
  - 横は中央基準なら位置のぶれ 0（左端・右端基準だと 2px。しゃがみでは中央 1px に対して 5px）
- 画像は余白を切り詰めて保存されているので、コマごとに幅・高さが違う。この基準で置いて初めて足元がそろう。
- 未検証: `turnX/turnY`（反転）時の基準、`ignoreDirection`。

### FD / FA ブロック（やられ判定・攻撃判定）の座標の意味

- **(x, y) = 矩形の中心**（キャラの原点＝足元から見た相対座標）、**width / height = 半分の幅・高さ**。
  矩形は `(x - width, y - height)`〜`(x + width, y + height)`。
- 検証: ゆいの弱キック（技 213）の攻撃判定がつま先を覆い、立ち（技 1）の当たり判定が全身を覆うのはこの解釈だけ
  （幅・高さを全幅と読むと、体判定が太ももしか覆わない）。
- `number` はスロット番号。同じ番号の判定は、上書きされるまで持続する。
- `y = 9899` や `2960` のような巨大な値は、画面外へ退避させて無効化する使い方と見られる。幅・高さ 0 も無効。
- ブロックは前から順に実行され、`I` はその `wait` の間止まる。
  → `I` の**後ろ**に置かれた判定は、**次の** `I` のコマから効く。
