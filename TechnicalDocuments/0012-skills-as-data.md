# 0012: 技はデータ（script.lton）とその解釈実行にする

- **日付**: 2026-09-29
- **状況**: 0005 の方式（FM2K のブロック列を技ごとの L^ コルーチンに変換）では、
  条件付きジャンプの多い技が `var^pc` の分岐ループになり、読めないコードになっていた。
  1 キャラ約 800 技を L^ としてコンパイルするのも重い（全体で 20 単位 → 今は 6 単位）

## 決定

- 変換した技は**データ**（`script.lton`）として持ち、`src/script.lh` が**解釈実行**する
- 手書きで書き直したい技は、今までどおり L^ のコルーチンで書き、`install` の後で `me.skills[n]` に入れる。
  技の表はどちらでも同じに扱う（併用）
- 理由:
  - 読めないのは、コルーチンのせいではなく元のジャンプの形のせい。データにすれば、ブロック 1 行ずつで原作と突き合わせられる
  - FM2K の動き（I の待ち、DS、ジャンプの行き先）が解釈側 1 か所にまとまる
  - コンパイルが軽い

## 形式（`tools/fm2k_convert/gen_script.py` が書く）

`assets/<characters|stages|system>/<name>/script.lton`:

- `layers`: `true^` なら E で終わる技の画像を消す（ステージ、システムの HUD）
- `settings`（キャラ）: 体力の最大、必殺ゲージ 1 本の点数、最大本数、開始時の本数
- `reactions`（キャラ）: `{ 反応番号, やられの技, スパークの技 }`
- `commands`（キャラ）: `{ name, time, skills = { 空中, 立ち, 立ち遠, しゃがみ }, directions, buttons }`
- 位置 = 技の番号: `{ name, level, blocks = { ブロック, ... } }`

ブロックは位置の並びで、先頭が種類、その後に数、最後に文字列（フラグやイベント名）が 1 つまで。
ジャンプ先は（技, ブロック）の 2 つの数で、技が −1 なら「なし」。

- `{ "Settings", レベル }` / `{ "Layer", 横%, 縦%, フラグ }`
- `{ "I", 画像, 待ち, x, y, フラグ }`
- `{ "FD", 番号, x, y, 幅, 高さ, 倍率, フラグ }`（幅・高さ 0 は消す）/ `{ "FA", 番号, x, y, 幅, 高さ, 威力, フラグ }`
- `{ "M", 速度x, 速度y, 加速x, 加速y, フラグ }` / `{ "S", 音 }` / `{ "E" }`
- `{ "SG", 技, ブロック }` / `{ "SC", 技, ブロック, 1 }` / `{ "SF", 技, ブロック, 回数 }`
- `{ "V", 変数, 操作(0 なし 1 代入 2 加算), 変数から(0/1), 値, 比較(0 なし 1 = 2 > 3 <), 比較値, 技, ブロック }`
- `{ "Rnd", 総数, より大, 技, ブロック }`
- `{ "COM", 時間, 技, ブロック, 数n, 方向×n, ボタン×n }`
- `{ "GL", 以上(0/1), 加算, 技, ブロック }` / `{ "GS", 本数, 以上(0/1), 加算, 技, ブロック }`
- `{ "DS", 技, ブロック, イベント }`（技 −1 は解除）
- `{ "O", 技, ブロック, x, y, 管理番号, 深さ, 出た時の技, ブロック, フラグ }`
- `{ "C", から, まで, 技, 条件 }` / `{ "R", 6 つの反応番号 }` / `{ "PS", 自分, 相手 }` / `{ "GP", 4 つ }`
- `{ "COLOR", 方法, r, g, b, a }` / `{ "EB", ... }` / `{ "AI", ... }` / `{ "RC", ... }` / `{ "RP", ... }`
- `{ "Nop" }`（読めなかったブロック、使わない DS）

## 解釈側（`src/script.lh`）

- `load(path)`: 読み込んで、ブロックを型付きの `Block`（種類、数の並び、文字列、COM の方向とボタン）にしておく。
  毎フレームの `fits^` を避けるため
- `run(me, script, n, at)`: 技 n をブロック `at` から実行するコルーチン。ブロックごとの処理は、生成していた L^ と同じ fighter.lh の手続きを呼ぶ
  - 同じ技の中のジャンプは `pc` を変えるだけ。ほかの技へは `jump` して終わる。**最後のブロックより先へのジャンプは技の終わり**
  - 1 ブロックごとに `spin` を数える（FM2K の 1 フレーム 300 ブロックの上限そのもの）
- `install(me, script)`: 技の表・レベル・反応・ゲージの設定・コマンド表を入れる
- `layers(script)` / `playersLayer(script)`: ステージのレイヤーの順番と、キャラを挟む位置

## 読み込みの時間

- ゆい（809 技）: 変換前の冗長な LTON（8.6 MB）で 0.95 秒。script.lton（1.35 MB）はそれより軽い。起動からウィンドウまで約 2.1 秒

## 確かめたこと

- ゆいの全 809 技を、生成した L^ とデータの両方で 300 フレームずつ動かし、毎フレーム
  （技、画像、ずれ、位置、速度、判定、オブジェクトの数）を比べた（使い捨ての trace_script.lh）。
  **808 技が一致**。残る 1 つ（#280）は、生成した L^ の不具合だった:
  途中から始まらない直線の技（#2）へ、最後のブロックより先（#2:34、#2 は 34 ブロック）へジャンプしたとき、
  L^ 版は先頭から走っていた。データ版は「技の終わり」で、取り決めどおり
- システム変数（128〜143）は全員のものなので、比べるときは片方ずつ保存・復元した（`clearSystemVars` を追加）
- 実機: 歩き・ジャンプ・超必殺・HUD・ステージが今までどおり動く。`trace.lh`（手書きの見本との比較）もデータ版で同じ結果
