# 0023: 場面ごとに素材をまとめて解放する（リソースアリーナ）

- **日付**: 2026-10-04
- **状態**: 実装済み。アリーナのスタック（選択画面の上に試合）、キャラ選択の顔グラ先読み、試合前の 2 キャラ先読み。試合 → 選択に戻る経路もユーザーが確認

## 背景

- 読んだテクスチャはキャッシュが持ち続け、解放されなかった（全部読むと RGBA で約 1.8GB。0021 で r8 にして約 1/4）
- LÖVE にリソースアリーナ（まとめて破棄する仕組み）は無い。オブジェクトごとの破棄は L^ の規約で **`dispose()`**
  （lhat-love は LÖVE の全オブジェクト型に `dispose` を付けている。LÖVE の `Object:release()` に当たる）
- 実測（640×480 前後の画像 50 枚、`love.graphics.getStats()`）:
  - 参照を捨てただけ: 51.1MB のまま
  - `L^.collectgarbage()` の後: 0MB（GC で回収されれば VRAM まで返る）
  - `dispose()`: 参照が残っていてもその場で 0MB

## 仕組み（`src/arena.lh`、`vp.arena`）

- **アリーナのスタック**（ユーザーの設計）。読むものは一番上のアリーナに入り、引くときはどのアリーナからでも見つかる。
  `pop()` は一番上のアリーナが読んだものだけを全部 `dispose()` する。アリーナが 1 つも無いときに読んだものは常駐（終了まで解放しない）
- 場面の流れ（`main.lh`）:
  - オープニング `[opening]` → タイトル（モード選択を含む）`[title]`（pop して push）
  - キャラ選択 `[select]`（pop して push）。**タイトルに戻るまで解放しない**
  - 両者決定 `[select / match]`（選択のアリーナは残したまま試合のアリーナを push）。試合が終われば試合のアリーナだけ pop して選択画面に戻る
- キャッシュ（Sheet の `images`・パレット、キャラの `sounds`）は世代番号を持ち、pop のたびに作り直す（残ったアリーナの物は引き直すだけ）
  - キャラの音はキャラとそのオブジェクトで共有（持ち主の `sounds`）

## キャラ選択と試合の読み込み

- 顔グラ（大）を、カーソルを合わせて初めて読むと、カーソルが引っかかる → **キャラ選択に入るときに全キャラ分を読む**
  - 読むのは各キャラの #25「キャラセレフェイス」から辿れる画像（`vp.script.imagesFrom`。#24・#25・#26 と、それが出すもの。1 キャラ 17 枚程度）
  - 全体の script.lton（テキストで 1 キャラ 0.5〜0.8 秒）を 10 キャラ分読むと、選択画面に入るまで 8 秒かかった →
    **`gen_script.py` が #25 から辿れる技だけの `portrait.lton` も書き出す**（他の番号は空の技。ゆいで 43KB）。選択画面はこちらで動かす → 1.0 秒
- 両者が決まったら、試合のアリーナを積み、2 人の全体の script.lton を読み、全画像を毎フレーム 6ms ずつ読む（`vp.sprite.loadAhead` / `loadSome`）。
  選択画面がそのまま読み込み画面になる。試合は、選択画面の待ち（100 フレーム）が過ぎて読み込みも終わってから始まる
  - 試合中に初めて出る技で止まるのは不可（ユーザー判断）。試合前に数秒待つ方がよい
  - 実測: ゆい 対 ゆい で 212 フレーム（約 2.1 秒）、テクスチャ 1,987 枚 / 202MB
  - ゆい 1 人の全画像: DDS（r8）904 枚 0.3 秒、PNG（RGBA）1,124 枚 1.1 秒（ファイルがキャッシュに無いときは計 7 秒）。VRAM は RGBA の PNG が 149MB を占める
- 開発中はテキストの LTON の解析が遅いが、配布物（VM のみ・fused）の LTON はバイナリ（`std.lton.load` で 535ms → 46ms）

## 実測（最初の 1 段の版。場面の切り替わりで全部解放していたとき）

- オープニング → タイトル: テクスチャ 7 枚 / 4MB → 3 枚 / 0MB
- タイトル → キャラ選択: 21 / 5MB → 4 / 0MB
- キャラ選択 → 試合: 37 / 6MB → 5 / 0MB
- 残る 3〜5 枚はアリーナの外のもの（フォントなど）で、増えていかない

## 補足

- L^ の `for^ i from^ A to^ B step^ S` の `step^` は正の量（負は仕様上誤り）。逆向きは `downto^`。
  `to^0 step^-1` と書いたら無限ループで固まった（コンパイラは負のリテラルを通した。lhat への論点）
