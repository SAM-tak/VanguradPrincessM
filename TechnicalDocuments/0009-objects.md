# 0009: オブジェクト（O ブロック）— ボイス・エフェクト・ヒットスパーク・飛び道具

- **日付**: 2026-09-28
- **状態**: 実装。ボイス、攻撃エフェクト、ヒットスパーク、ゆいの花びら（撒いて、撃つ）が動く

## ボイスが鳴らなかった理由

- 技を振ったときの **SE は技本体の S ブロック**なので鳴っていた
- **ボイスは O ブロックで生成する「見えないオブジェクト」**が鳴らしていた。オブジェクトが未実装だったため鳴らなかった
  - ゆいの #352（技名8）がボイス専用。画像を y = 10000（画面外）に置いて S で台詞を鳴らし、すぐ終わる
  - 技ごとに開始ブロックを変えて台詞を選ぶ（弱キックは `#352:59`）。管理番号 3 なので、新しいボイスが前のボイスを置き換える

## O ブロックの意味（2DFM_Player の ObjectCmd と 0005 のコミュニティ資料より）

- 技 (n, b) を走らせる**別の実体**を生成する。キャラの技表・画像・効果音を共有し、生成時の向きを受け継ぐ
- 位置: 生成した者から (x, y)（x は向きで反転）。`picXY` なら視界（640×480）の座標
- 描画の奥行き: `out` = キャラより手前（127）、`point` = 指定の深さ、どちらも無ければ奥（0）。キャラは 70〜80
- `parent`: 持ち主と一緒に動く
- 管理番号 0〜9: `unCond` でなければ、同じ番号の既存オブジェクトを消して置き換える
- 「It's out」の技（outSkill）は未使用（2DFM_Player でも用途未確定）
- オブジェクトはスクリプトが終わる（E / 最後まで行く）と消える。ループし続けるものは、置き換えられるまで残る

## 変数の置き場（重要）

- **タスク変数（0〜16）**: 技・オブジェクトそれぞれのもの
- **キャラ変数（64〜79）**: キャラと、そのオブジェクト全部で**共有**
- **システム変数（128〜143）**: 全員で共有
- ゆいの花びら（#270 ハナビラキダン）は、キャラ変数 P（79）が 1 になると発射（#271 / #273 キダン発射）へ移る。
  236+A（#269）が P を 1 にする。オブジェクトがキャラ変数を共有しないと撃てない
- データ変数: 192 / 193 = 自分の x / y、196 / 197 = 親（持ち主）の x / y

## ヒットスパーク

- 受ける側の hit-junction 表の「スパーク」列の技を、受ける側のオブジェクトとして、攻撃判定とやられ判定の重なりの中心に出す（最前面）

## オブジェクトの攻撃判定

- オブジェクトも FA / R / PS を持ち、相手に当たる（飛び道具）。当たった後の DS「attacking」もオブジェクト自身に届く

## 実装（`src/fighter.lh`）

- `makeObject` / `spawn` / `stepObjects` / `drawObjects`、視界位置は `setView`
- Fighter に `owner`（持ち主）、`objects`、`slots`（管理番号）、`depth`、`follow` を追加
- オブジェクトの位置は世界座標。`parent` のものは毎フレーム持ち主の移動分だけずらす

## 色の不具合 2 つ（修正済み）

飛び道具が青緑の網点の帯に見えていた（原作は加算の桜色の弾）。原因は 2 つ:

1. **キャラの RGBA 画像までパレットを通していた。** エフェクトの多くは専用パレットの画像（RGBA で書き出し）なのに、
   Sheet がキャラの全画像をパレットシェーダーに通し、赤の値をパレット番号として引いていた。
   → Sheet が `images.lton` の format を読み、`indexed` の画像にだけパレットを当てる
2. **COLOR の RGB を反映していなかった。** COLOR の r g b は **符号付き −32〜+32 の加算量**（バイト 246 = −10）で、
   各チャンネルに 値 / 32 を足す（2DFM_Player のシェーダーと、wanwan の資料の「colorR/G/B は [−32, +32] に制限」から）。
   ビーム #290 の (2, 246, 246) は (+2, −10, −10) = 赤を足して緑・青を引く → 桜色
   → スプライトのシェーダーで tint を足す（パレット画像・RGBA 画像の両方）
