# P2: V演算・座標読み取り・変数の寿命

2026-10-07。0074のP2を実装。根拠は原作 `vanpri108/ヴァンガードプリンセス/ヴァンガードプリンセス.exe` の `build/original-corner-disasm.txt`。別ビルドの推測からではなく、使用している原作EXEを照合した。

## 確認した処理

| 原作アドレス | 処理 | 反映 |
| --- | --- | --- |
| 0x4137A4–0x4137E7 | 変数番号の上位2ビットでオブジェクト／キャラ／システムを選び、下位6ビットでword配列へアクセス | `home()`のオブジェクト範囲をbank 0へ統一 |
| 0x413813–0x413846 | 変数オペランドを16ビットで読む | 演算オペランドを符号付き16ビットへ正規化 |
| 0x413862–0x4138A8 | 自分・親の16.16座標をゼロ方向へ整数化。カメラ座標は整数値を読む | V192〜197を整数化。物理・描画座標そのものは変更しない |
| 0x4138F0–0x413917 | 既存値とオペランドを符号拡張して加算し、-30000〜30000に飽和 | `addv()`で実装 |
| 0x41391D | 代入は単なるword書込みで飽和なし | `setv()`は16ビット化のみ。32767も代入可能 |
| 0x413921–0x41395C | 演算後のwordを符号付き比較 | 既存の分岐順を維持し、飽和後に分岐する回帰テストを追加 |

代入と加算を同じclampにはしない。例えば代入32767は32767、そこへ0を加えると30000になる。32768の代入は-32768。座標-12.9を読むと-12であり、floorの-13ではない。

## 共有範囲と寿命

有効なユーザー変数は各bankの16個（0〜15／64〜79／128〜143）。現行dataを走査し、V命令の対象がこの範囲内にあることを確認。予約領域の原作メモリ破壊を再現するものではない。

- タスク変数は本体・各生成オブジェクトそれぞれに独立する。新しいオブジェクトは0から始まる。
- キャラ変数は本体・その子・孫で共有し、対戦相手とは分離する。
- システム変数は双方とオブジェクト間で共有する。既存のシーン／試合初期化でリセットする。
- タスク変数は技ごとではなくオブジェクトの寿命に属する。原作の技開始0x410CF0/0x410D50は判定・キャンセル・DS・待ち・運動等を処理するが、+0x131の変数配列を消さない。`play()`にあった技開始ごとの変数消去を撤去。SG・DS・被弾開始でも保持する。
- ラウンド配置時の既存`p.vars := {}`は維持する。原作にもキャラ初期化0x4121CCで16wordの消去がある。

V198の時計・V199のラウンド番号、コンボ表示用V128のスナップショットは変更していない。シーン間の独自フローも今回の対象外。

- 各bankの先頭・末尾6スロットで±30000、±32768、符号付きword折返し、飽和後の逆方向加算。

- 本体／子／孫／相手間の共有と独立、システムリセット。
- 通常開始／SG／DS／被弾開始でタスク値を保持し、新規生成には引き継がない。
