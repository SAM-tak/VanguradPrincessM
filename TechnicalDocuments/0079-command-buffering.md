# 0079: コマンド表の先行入力と硬直終了時の受付

## 調査

ゆい6B→214Bは、PS修正後も実操作では赤コンボになるとの報告。
えりの実データで停止直前の受け身分岐を12フレーム止め、待ち時間・技番号・V128が
進まないことを確認した。受け身不能時間だけが停止中に進む現象は再現しなかった。

最速の214Bでは2・3ヒット目ともV128=0。開始を2フレーム遅らせると、えりは
frame 128で#163へ入りV128=1になり、frame 131の追撃は赤になる。
従来テストはヒット数だけの確認だったため、色の検証を追加した。

## 原作の履歴検索

原作ゲームEXE `0x410060` のコマンド表照合では、現在フレームで最後の入力が
一致しなくても過去へ検索を続ける。

- `0x4100EB–0x41011B`: コマンドごとの受付時間を取得。
- `0x410719–0x41071C`: 入力不一致でも `0x410863` へ。
- `0x410863–0x41087C`: 履歴位置と残り受付時間を減らして照合を続行。
- `0x4102C3–0x4102E1`: ボタンの押下エッジを履歴から照合。

移植の `entered` は最終ステップが現在フレームで不一致だと即falseを返していた。
この制限を撤去し、コマンド固有の時間内にモーション全体が収まれば成立させる。
独自の固定長キューや、受付時間が無限に延びる「予約技」は作らない。

## 実行の可否

- `takeCommand` にコマンド成立と実行可否の判定をまとめ、ゲーム本体とテストで共有。
- ヒットストップ中も入力履歴へ記録するが、技変更・基本移動は行わない。
- `mayStart` はヒットストップ中false、終了済みの技ではtrue。
  以前は終了済みでも旧技のC制限で弾き、そのフレームのボタンを取り落としていた。
- 技内COM・サポート用の履歴を消費しない。プレイヤーごとの履歴は従来通り独立。

今回、チャージ・連打・入力方向反転など他の未対応仕様を完全実装したものではない。

## 検証

- `tests/yui-link.lh`: 214Bをframe 94で入力完了し、その後はボタンを離す。
  frame 107の硬直終了直後に発動する。通常10キャラ×左右端で、
  6B→214Bの3ヒットが全て通常色となり、続く623Bは当たらないことを検証。
- `tests/vm-audit.lh`: 停止中の受け身分岐凍結、停止中に蓄えたコマンドの実行、
  入力時間の境界・期限切れ、実行中の同じ技の再起動防止、2Pへの履歴漏洩防止、
  COM用履歴の維持。
- `combat-flow`、`support-flow` で既存戦闘とサポート入力を確認。

中央での間合いの問題（0078）は、この入力受付の変更とは別の未確認事項。
