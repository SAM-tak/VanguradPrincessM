# 持続判定の再ヒット・連続ガード・EBの揺れ

## 原因と修正

### 持続判定

従来は `Fighter.struck()` が命中時に `hits` を空にするだけだった。
次のFA命令で当たり判定が作り直されると再び命中できた。
ナタリア（データ名「カテジナ」）の「足払い」#239は、同じFA #0を
威力120 → 101 → 60 → 40、持続4 → 4 → 4 → 3フレームで更新する。
したがって、この例の原因は厳密には毎フレームの命中ではなく、持続中のFA更新による再命中。

実行中の攻撃に `attackConnected`、各Boxに `connected` を保持する。
命中／ガード時には、その時点の攻撃判定をまとめて命中済みにする。
通常のFAの形状変更や、一部のFAの削除は命中履歴を消さない。
全FAを削除した場合は、その判定群の履歴を終える（[0050](0050-yui-super-finisher.md)で修正）。
新しい技を `begin/play` で開始すると履歴を消す。スクリプトの `start/SG` では引き継ぐ。
`combo`（FM2KのCont.Hits）指定で新しく設置されたFAは追加の命中を許すが、
同じ判定の持続フレームごとには命中させない。同時に設置された複数FAも一度に消費する。
これは現在の1対1の攻撃元／対戦相手モデルでの管理。対象ごとに独立した命中履歴は持たない。

多段技の実例として、ナタリア「けつ昇竜」#229は通常FA（威力100）の後に
`combo`付きFA（威力31）があり、2ヒットを維持する。
FAの幅・高さは、どちらかが0なら判定削除とする。

### 連続ガード

`main.lh` が「通常動作中だけガード可能」と判定しており、
ガード反応技に入った次のフレームからガードできなくなっていた。

ガード反応中の状態を `blocking` として保持し、`updateGuard()` は
通常動作中またはガード反応中の後ろ入力を受け付ける。
しゃがみ判定も現在の入力方向から渡すので、ガード反応技の番号によって立ち扱いにならない。
新しい行動・被弾ではガード反応状態を解消し、通常のやられ硬直からはガードできない。
後ろ入力を離せばガードを解除する。空中の反応完了から落下に移る際にも状態を解消する。

CPUもヒットストップ／ガード反応中は方向入力を保持する。
従来はヒットストップ中にニュートラルを返していた。

### EBの画面揺れ

抽出データには `shakeBgX/Y = { type, shake, duration }` があったが、
`gen_script.py` と `gen_skills.py` が破棄し、`Fighter.screen()` も未実装だった。
EBの実行用形式を以下に拡張する。

```
{ "EB", fading, r, g, b, a, duration,
  xType, xAmplitude, xDuration, yType, yAmplitude, yDuration, flags }
```

`src/shake.lh` のAxisが各軸を100fpsで進める。0は指定なし、1は減衰、2は増幅、
3は一定、4は乱数振幅とし、符号はフレームごとに交互にする。
0の軸は他オブジェクトが開始した揺れを消さない。
単一フレーム指定でも振幅を出し、指定時間の終了時には0へ戻す。

背景・キャラクター・エフェクトの描画に共通オフセットを加える。
物理座標、当たり判定、カメラの追従目標、スクリプトのカメラ座標変数は変えない。
システムHUD／ラウンド表示は固定。キャラクター所有の画面座標オブジェクトには揺れを適用する。
ポーズ中はtickが止まるため揺れも停止し、ラウンド開始時にリセットする。
EBの色効果は今回の実装対象に含めていない。

## データ復元

`tools/fm2k_convert/restore_shake.py --apply` で未加工の
`assets/**/skills/*.lton` からEBだけを復元した。
名前・EB列の既存オペランドを照合し、候補が曖昧なら書き込み前に失敗する。
共有サポートと共通補助技は、従来の方針どおりゆいを正とする。
技番号・分岐先・ブロック数・素材参照・手修正は維持。
実行用15ファイル645命令と、対応する変換中間15ファイル645命令を更新。
再実行時の変更は0。今後のJSONからの変換でも両軸を保持する。

## 根拠と検証

技の判定更新・多段指定・揺れの数値はリポジトリの未加工抽出データを確認。
EBの方式およびFAのCont.Hitsの解釈は
[wanwanのFM2K解析資料](https://github.com/Armonte/wanwan/blob/main/docs/editor/2DFM%20Codeblocks.md)、
FAのゼロサイズ削除は
[命令ディスパッチャ解析](https://github.com/Armonte/wanwan/blob/main/docs/editor/opcode_dispatcher.md)も参照。
揺れ波形の補間や命中グループの細部は移植側での実装であり、原作実行ファイルとの全技・全フレーム比較を済ませたものではない。

- `combat-flow`: 実データの足払いが1ヒット120ダメージ、けつ昇竜が2ヒット131ダメージ。
  再度技を出せば命中できることも確認。
- 同テストで連続ガード、下段の立ち／しゃがみガード、解除、被弾中のガード禁止、
  CPUの入力保持、同時FAの重複命中防止、FA更新・削除後の履歴維持を確認。
- 揺れの減衰／増幅／固定／乱数範囲・終了・独立した軸の時間・原作EBの実行を確認。
- `story-flow`: 選択からCPU戦、勝利、次の試合まで通過。
- `support-flow`: 全キャラ275通りの入力と分岐、同期読み込みなしを確認。
- 既存Pythonテスト22件と追加の変換テスト4件が成功。main.lhのコンパイル成功。
