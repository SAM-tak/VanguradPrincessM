# コマンド成立時の古い入力履歴の消費

2026-10-07。押下判定をf458b60でコミットした後の作業。

## 原作の処理

`build/original-corner-disasm.txt` の `0x41073E–0x41077C` は、コマンド表の全ステップ成立後、timeが29を超える場合に履歴を消去する。現在のリング位置から20を引いた枠を起点に、古い方向へ1004枠をゼロ化する。1024枠のうち現在〜19フレーム前だけが残る。

この処理は姿勢別の技番号選択より前で、技番号0の場合も実行される。技内COMの検索には同じ消去処理はない。

## 実装

`fromCommands` で全ステップ成立後、time > 29なら `consumeCommandHistory` を呼ぶ。通常の判定だけを担う `entered` および技内 `command` では消費しない。

消去済み範囲の絶対フレーム番号を記録して、以降は新たに消去対象になった枠だけを更新する。履歴の一周にも対応し、1回の更新対象は最大1004枠。未記録枠は元からニュートラルなので作らない。コマンド走査ごとの追加テーブル生成はない。

原作は保持状態からその場で押下を計算する。一方こちらは押下を事前計算しているため、消去により直前フレームがゼロになった「残る最古の1枠」の押下マスクを再計算する。これがないと消費後の押下判定が原作とずれる。lastButtonPressキャッシュは過去枠の更新で新しい時刻を上書きしない。消去済みの古い時刻が残る場合も、それは高速除外を減らすだけで、実際の履歴照合で不成立になる。

## 検証

`tests/command-modes.lh` に29/30境界、方向・ボタン両方の消去、技番号0でも消費、COMが消費しないこと、直近入力の保持、20/19フレーム境界、連続消費、1024枠一周後を追加。既存の4032通りの押下、連打・溜め・近遠選択も維持。

実データの `tests/yui-link.lh` と `tests/support-flow.lh` も回帰確認。

方向履歴の向き変更と回転入力の順序は未完了。今回の対応範囲は履歴消費のみ。
