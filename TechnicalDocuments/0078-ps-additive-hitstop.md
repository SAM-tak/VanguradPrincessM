# 0078: PSの加算式ヒットストップと、ゆい6B→214B

## 問題

DS遷移時のFD初期化を実装した後、ゆい6B→214Bが画面端のえりに入らなくなった。
ダウン後のFDを残すことで直すと、禁止されるべきダウン追撃まで復活するため、
攻撃側と被弾側の時間進行を照合した。

## 原作EXEの根拠

`ヴァンガードプリンセス.exe` のPS処理は、停止時間の**代入ではなく加算**。

- 自分: `0x413641–0x413653`。指定値0はスキップし、非0はオブジェクトの
  `+0x40` にある残り停止時間へ `add` する。
- 相手: `0x4136AE–0x4136FB`。同じく0をスキップし、残り時間へ `add` する。
- エディター側の逆コンパイルには代入式の版がある。今回のゲームEXEとは異なるため、
  ゲームEXEの命令を根拠とする。

`Fighter.pause` は以前、両方へ代入していた。`PS 0, n` が自分の停止を解除し、
`PS n, 0` が相手の停止を解除してしまう。

## コンボでの影響

- ゆい6Bは#240。ヒット時のDSで#242へ移り、`PS 0, 10` を実行する。
- えりの被弾#155は `PS 0, 22` を実行する。
- 旧実装では、後から走る#155が、直前に設定された自分の停止時間を0へ戻す。
  被弾側が早く落下し、214Bが届く前に着地してFDが消える。
- 加算へ修正すると停止が維持され、空中にいる間に214Bが当たる。

右端・初期位置1170/1230のテストでは、6B接触がframe 40、214B開始が107。
旧実装は214B不発。修正後はframe 126で214Bの初段、173で次段が当たる（えり）。
この修正で6Bの画像待ちや硬直時間は変更していない。

なお214Bは#276（FM2K方向コード4,5,6）、623Bは#267。
#277は別の入力の技で、214Bの検証には使わない。

## 検証

- `tests/vm-audit.lh`: PSの0指定で残り時間を維持することと、非0指定の累積。
- `tests/yui-link.lh`: 通常10キャラ、左右端の20ケース。
  6B→214Bが合計3ヒットし、続く623Bは当たらない。
- 既存の `combat-flow`、`sweep-down`、`vm-audit` を再実行。
  連続ガード、超必殺技、ダウンFD消去、追加コマンドの回帰を確認。

画面中央・初期位置580/640では、移動を挟まず硬直終了直後に214Bを出すと
横の距離が足りない。中央での原作の入力手順は確認中で、上記20ケースには含めない。
