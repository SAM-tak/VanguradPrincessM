# えこの独立パレットと画像統合

## 方式

`tools/fm2k_convert/support_palettes.py` で、サポート所有の DDS を寸法と画素の色番号パターンで分類する。画素の初出順に色番号を正規化した結果が完全一致する画像のみを統合する。余白の切り詰め、類似画像の推定、減色はしない。RGBA PNG は今回の対象外。

代表画像の色番号に対して、参照元の元パレット全8行から RGBA を対応付ける。同一キャラの画像間で対応が衝突しないものは一つのパレットにまとめ、衝突する場合のみ追加のパレットを作る。全画素・全8行の RGBA 一致を検証してからマニフェストを更新する。透明画素の RGB も一致条件に含む。

`images.lton` の indexed エントリーに `palette = "data/supports/えこ/palettes/...png"` を追加。生成パレットは Git 管理の data に置き、代表画像は assets の既存 DDS をそのまま使う。キャラ本体や別サポートからの参照でも、画像エントリーが指定するパレットを使う。指定のない画像は従来どおり所有キャラのパレットを使う。

描画側はパレット Texture を画像番号ごとにキャッシュし、アリーナ世代変更で破棄する。ロード側も同じパレット解決関数を使い、使用画像に必要なパレットのみ先読みする。描画ごとの Texture 作成や色番号変換はない。8色の選択番号は変更しない。

## 適用結果

- えこの DDS 226枚を114枚に統合。未参照の112枚、3,241,335バイトを削除。
- キャラ11人と旧 common の計12マニフェスト、1369エントリーを更新。
- あやね・サキは各2組、他9キャラは各1組、common は1組。256×8 RGBA の計14枚、PNG合計8,683バイト。
- PNG画像、技定義、表示寸法、画像番号、原作の色は維持。
- 他のサポートには未適用。114枚が見た目から判断した理論上の最小枚数という意味ではない。

## 再生成

素材の共有化・所有先整理の後に実行する。

```powershell
python tools/fm2k_convert/support_palettes.py assets --support えこ
python tools/fm2k_convert/support_palettes.py assets --support えこ --apply
```

指定なしでは読み取り専用。適用時はパレットの保存結果も確認してから参照を更新し、data 配下の全 images.lton（変換中間データを含む）に参照が残らない重複ファイルだけを削除する。再実行は差分なし。元画像への復帰・再抽出は通常の変換手順から行う。今回の作業前データはローカルの `build/eko-before-palettes.zip` に退避した。

## 検証

- `tests/test_support_palettes.py`: 色番号の同型判定、不正対応の拒否、衝突時の分離、全8色の保存、削除、再実行の安定性。
- `tools/test-async.ps1 -Test support-palettes`: 全11キャラについて必要画像・パレットの先読みと全8色のシェーダー描画、アリーナ切替を検証。同期読み込みなし。
- 適用後の再実行でマニフェストのハッシュが不変。

既存 selective-preload は「未選択サポートのディレクトリを一切参照しない」という条件が、かなえ所有画像の他サポートからの参照と矛盾して失敗する。これは今回のパレット追加箇所に達する前の失敗であり、成功扱いにしない。上記の専用テストでは、実際に選択された技から必要画像を列挙して検証する。
