# 配布ビルド前のエンジン互換性検証

2026-10-08。

通常版lovecはAPI署名をテキストから登録するが、VM-only版は埋め込みSignatures.hを読む。このためゲームのコンパイル成功だけでは、配布用VMの署名表・組み込みユニット・言語コアの整合性を保証できない。DLLの更新日時比較も十分ではない。

tools/check.ps1は小さなゲームとconf.ltonをbuild/engine-check/<GUID>に生成し、配布ビルドに使うlovecでコンパイル、その結果を配布用love.exeで実行する。ウィンドウは非表示、両プロセスには--no-error-screenを指定。終了コード0に加えてゲームのloadから出す実行ごとの成功マーカーを確認する。標準出力・標準エラーは非同期に読み出してログ保存し、各プロセスの既定タイムアウトは30秒。タイムアウト時は子プロセスツリーを終了する。

単独実行:

```powershell
pwsh -NoProfile -File tools/check.ps1
pwsh -NoProfile -File tools/check.ps1 -Love 'C:\path\to\lhat-love' -TimeoutSeconds 30
```

dist.ps1は既存のVMビルド判定・必要時の再ビルド直後、素材コピー・既存出力削除より前に呼ぶ。両VS Code配布タスクに適用される。失敗時はthrowでタスクを失敗させ、ログの場所と署名生成物の再生成・VM再ビルド方法を表示する。チェック自体はエンジンのソースや生成物を変更しない。

検証:

- 現在の実lovec→配布用VMで成功マーカーと終了コード0を確認。
- ビルド領域の専用テスト実行ファイルで、終了コード7、終了コード0だがマーカーなし、タイムアウトを注入し、すべて非0終了することを確認。
- 同じ失敗用VMをdist.ps1から指定し、stagingより前に終了コード7の診断で停止することを確認。
- 今回はゲーム全体の配布ビルドは行っていない。これはエンジン起動互換性の検査であり、ゲーム全機能の実行試験ではない。
