## 技の書き方

**技 = Fighter を受け取る `p^`。1 フレームごとに `yield^` するコルーチンとして走る。**

FM2K のブロックを手続きにしたもの（`src/fighter.lh`）:

- `I` → `await^ show(me, 画像, wait, x, y)` — 画像を出して wait フレーム待つ
- `FD` → `hurt(me, スロット, x, y, w, h)` / 押し合い判定は `body(...)` / 消すのは `noHurt`
- `FA` → `hit(me, スロット, x, y, w, h, 威力)` / `noHit`
- `M` → `move(me, vx, ax)`（1/100 px/フレーム）
- `S` → `sound(me, 番号)`
- `SG`（技内ジャンプ）・`Rnd`（乱数分岐）→ L^ の `repeat^` / `if^` / `for^` そのもの
- `E` → 手続きの終わり

例（立ち。5 回に 1 回まばたきから始まる）:

```lhat
public^let^stand = p^me:Fighter{
    repeat^{
        standBoxes(me)
        if^love.math.random(0, 9) > 7 {
            await^show(me, 20, 7, -40, 25)
            ...
        else^:
            await^show(me, 8, 7, -40, 25)
            ...
        }
        ...
    }
}
```

FM2K ではブロック番号へのジャンプ（`SG #1:21`）で書かれていた合流が、
構造化された分岐とループになる。共通部分は `crouchCycle` のような小さな手続きに切り出せる。

## L^ について分かったこと（lhat-love 2026-09-28 ビルド）

- **終わらない技と終わる技は型が違う。** `repeat^{ … }` だけの技は `c^{p^-> nil^ -> -}`、
  終わる技は `c^{p^-> nil^}`。互いに代入できないので、`Skill = c^{p^-> nil^}|c^{p^-> nil^ -> -}` を定義して両方を受ける。
  進めるときは `fits^` で絞り分ける。
- 書式指定は printf 形式: `$"{i:%04d}"`（`{i:04}` は実行時エラー）
- 初期値を持たない `def^` のフィールドは `abstract^名前 : 型` と書き、`override^new` で埋める
- `p^` の本体の最後の式は答えにならない。`return^` が要る
- `require^"src/fighter.lh"`（`let^` なし）で、単位が名乗ったパス（`vp.fighter`）の下に入る。型としても `vp.fighter.Fighter` と書ける
- `std.lton.load` の答えは `t^{}` なので、中身を使うには 1 つずつ `fits^` で絞る必要がある。
  見本では画像のファイル名が番号から決まるため、LTON は読んでいない

## 未対応（見本の範囲外）

- 左右の向き（反転描画、`turnX`、`ignoreDirection`）
- 変数（V）、キャンセル（C）、ヒット時の反応（R）、エフェクトのオブジェクト（O）、DS、COM、残像（AI）、色（COLOR）
- 前歩きの `Unknown` ブロック（fm2ndparser が解析できないもの。足音などの可能性）
- `rgba` 形式の画像（エフェクト）をパレットなしで描く分岐。いまは Sheet が全画像にパレットシェーダーを当てる
- 相手・当たり判定の衝突・ダメージ
