# 回転入力の順序判定

2026-10-07。履歴消費を607d00aでコミットした後の作業。

原作EXE `0x41061A–0x410717` と分岐表 `0x410A00/0x410A28/0x410A38` を照合。履歴を逆順に読み、最初の有効方向から2系統の回転カウンタを始める。以降は時計回り・反時計回りの次の上下左右と一致したときだけ進める。不一致は無視し、斜めは開始位置の決定にだけ使用する。開始時の残量はamount×4で、進行ごとに1を引き、どちらかが2未満になれば成立。amount=1は開始方向と続く3方向、amount=2は開始方向と続く7方向になる。

以前の実装は方向のビット集合だけを取り、順序を検査せず、斜め1回で2方向分を加算していた。これを原作の2系統の追跡に置換。共有グローバル状態も除去し、判定呼出し内の数値変数だけで追跡する。

`tests/command-modes.lh` に両回り、異なる開始位置、順序違反、斜めのみ、3方向だけ、2回転の受付窓境界を追加。既存入力テストおよび連続技・サポートの回帰テストも実施。mode3は現データの使用例を前提とせず、人工コマンドで検証している。

向き変更時の方向履歴は残件。原作は物理方向の履歴を読み、現在の向きと設定フラグに応じて照合方向を切り替えている。現行の記録時に相対方向へ変換する方式との違いはあるが、設定フラグの扱いを確定する前に一律反転へ変更しない。
