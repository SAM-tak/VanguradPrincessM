# SC/SFの復帰先スロットと終了・分岐

2026-10-08。向き変更の検証を14580d2でコミットした後の作業。

## 原作の状態

原作EXEの命令分配は命令番号から1を引いてジャンプ表を引く。ルナ#37:28のSCは.player上のopcode11（生データ0b22012a…）で、実行先は0x412A2F。SFはopcode9で0x4129A9。

- SC `0x412A2F–0x412A76`: actor+0x85に現在技と呼出し位置を保存。単一スロットなのでSCをさらに呼ぶと上書きされる。
- SF `0x4129A9–0x412A2A`: +0x7Cに反復回数、+0x7Dに反復対象、+0x81に復帰先。SCとは別のスロット。回数0、対象技0は何もしない。
- E／通常の末尾到達 `0x412625–0x4126D9`: SCの復帰が優先。SCスロットを消し、その呼出し直後へ進む。SCがなければSF回数を減らし、残りがあれば対象を再実行、0なら呼出し直後へ戻る。
- SGはこれらを保持する。SCの呼出し先で別技へSGし、その先でEになっても元のSC復帰先へ戻る。
- 通常開始・被弾と一般DSは `0x410D50` 等を通じてメインキャラの復帰状態を消す。着地専用経路は保持。
- 明示Eの生成物・システムはメインと異なり、復帰処理へ入らず終了側へ進む。

## 変更

従来はL^のコルーチンを入れ子にawaitし、SFはforで呼出しを繰り返していた。この方式ではSC→SGの際に呼出し元の続きを先に実行したり、原作にない多段復帰ができてしまう。

FighterにSC/SFの固定スロットを追加し、Scriptの呼出し・復帰もSGと同じ継続遷移として扱う。一般DSと通常開始で破棄し、SGと着地では保持する。SC先のEでレイヤー画像を先に消すことも避ける。手書きL^用のcallヘルパーは残し、FM2K命令はscriptCallを使う。

旧L^技生成器も同じAPIを出力し、呼出し直後を再開ラベルに含める。技データの再生成は不要。

- `tests/combo-correction.lh`: 呼出し中のEでコンボ補正のカウンタを誤って解除しない。

原作は不正な呼出しやループにも固定スロットの結果を適用する。移植側は既存の1フレーム実行上限を維持する。全ての無効データについて原作の暴走まで再現するものではない。
