# 残るイベント経路と戦闘フレーム順の実装

2026-10-07。0082で挙げたlanding / attacking / defending / wallHittingの残件を実装した。根拠は原作EXEの逆アセンブル `build/original-corner-disasm.txt`。L^コア、lhat-love、キャラクターの技定義は変更していない。

## フレーム順と予約遷移

原作の `0x404CD0` は `0x404D6F → 0x40C130` で各アクターのスクリプトを処理してから、`0x404D8B → 0x40FFC0` の衝突・移動処理へ進む。後者の順序はFA/FA接触 (`0x40EB60`)、FA/FD命中 (`0x40F010`)、移動・壁・押し合い (`0x40F910`)、本体の命中イベント確定。

戦闘の `stepFighters` をこの順序に分離した。本体と子オブジェクトに `stepScript` と `moveStep` を用意し、単独シーンで使う従来の `step` は移動とスクリプトの組を維持する。

`0x412327` の予約DSはヒットストップの減算と着地より先に処理する。`0x40F541` の被弾反応も即時実行ではなく予約する。命中判定の途中で相手のFAを消さないため、先に走査された側だけ相打ち不能になることを防げる。予約済み反応は通常入力・向き直りで上書きしない。移動時の壁イベントは先行する衝突イベントを上書きできる。

## landing

`0x411867–0x411911`（本体）と `0x41241C–0x4124AE`（生成物）の専用経路を分離。接地時に位置と運動を止め、登録されたlandingだけを消費し、待ち時間・FA・FDを消して指定ブロックへ進む。他のDS登録、C、Rは維持する。本体は被弾／ガード状態を終了させ、生成物はその状態を保持する。

一方、一般の予約DSは `0x40E540` を通ってRも消す。0075にあった「一般DSでもRを維持」は誤読だったため訂正し、回帰テストも修正した。着地専用経路との違いを明示的に検証している。

## attacking

`0x40F358–0x40F36A` の生成オブジェクトへの命中を追加。相手の本体だけでなく生成物のFDも走査する。生成物への命中は攻撃グループを消費し、攻撃者のattackingを通知するが、本体への命中と同じHP減算・被弾技・コンボ・ヒット演出は発生させない。組み込みの影とシステム用アクターはこの対象から除外する。

## defending（特殊なFA/FA接触）

`0x40EF33–0x40EF99` の条件は「片方だけ威力0、かつどちらかのFAに0x8000」。該当時は接触FAを無効化し、生成物のdefendingを発火する。offsetWayと併存する場合は後からdefendingが予約を上書きする。両方威力0の場合はFA配列消去だけでイベントを起こさない。

このビットはJSON抽出器の `halfed` とは別物。halfedは0x0004でガード時の削りに関係する。新しい内部名を `projectileCancel` とし、`gen_script.py --player` で元バイナリから補完する。全14個の.playerを調べた範囲では0x8000の使用は0件だったため、既存データの再生成は不要。人工FAによる条件テストと、抽出器のビット分離テストで検証した。原作はFAブロックの先頭を無効化するが、本実装では共有技定義を変更せず、実行中の該当判定スロットを消す。

## wallHitting

`0x40FAC3` 以降の登録有無による分岐を反映。wallHitting登録中は画面端の境界を使い、未登録時は通常のステージ／画面制限を使う。専用の `wallMinX / wallMaxX` を導入した。命中の後に移動・壁判定を行うため、壁DSと命中DSの競合も原作の順になる。
