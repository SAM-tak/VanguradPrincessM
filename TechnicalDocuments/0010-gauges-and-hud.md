- **日付**: 2026-09-28
- **状態**: 体力・必殺ゲージの増減と表示、システムの HUD（枠・名前・VS MODE など）、キャラごとの HUD（STUN・Ca・SUPPORT など）が出る

## ゲージの値

- キャラ設定（`.player`）: ゆいは体力 1000、必殺ゲージ 1 本 300、最大 5 本、開始時 4 本
- 必殺ゲージは「点数」で持つ（1 本 = `specialPer` 点）。本数（レベル）= 点数 / 1 本の点数（切り捨て）
- **GP**（`gauges`）: 自分の体力・必殺、相手の体力・必殺に加算。例: `(0, 8, 0, 16)` = 攻撃で自分 +8、相手 +16
  - オブジェクトの GP は持ち主のゲージに効く。相手は Fighter の `enemy`
- **GL / GS** は分岐。**条件が成り立てば今の技を続け、成り立たなければブロックの技（「失敗したら」の技）へ**（コミュニティ資料より）
  - GL: 体力が値より上（isMore）／下
  - GS: 必殺ゲージの本数が値以上（isMore）／未満。成り立ったら「加算」本数を足す（負なら消費）
  - 比較の向きは資料の表現があいまいなので、データの使われ方から決めた（仮定）。
    例: 超必殺「チョウヒ実行」（#279）は `GS 4 本以上` を満たさないと #234 強斬りになる

## HUD（システム側）

システム（.kgt）の技を、キャラ・ステージと同じ生成器で L^ にした（`gen_skills.py <kgt json> system --out src` → `src/system/`）。
組み込み技の番号（KGTBuiltInSkills）:

- ステージレイアウト 1〜10（#57〜#66）: 名前・VS MODE・ゲージの枠・SPECIAL / SUPPORT の枠など。画面座標、**左上基準**で描く
- 1P / 2P 体力ゲージ（#67 / #68）: 画像 #7（230×6）を (60, 44) と (350, 44)（2P は左右反転）にフェードインで出す
- 1P / 2P 必殺ゲージ（#69 / #70）: 画像 #63（67×4）を (30, 462) と (543, 462)
- 位置だけの技: タイマー（320, 65）、顔、必殺ストック数（12, 476）など

エンジン側の仕事（`src/hud.lh`）:

- ゲージの技の画像を、値の割合で**切り取って**描く
  - 体力: 残りを中央寄りに残し、外側から減る（2P は反転しているので同じ見た目になる）
  - 必殺: 今のストック内の溜まり具合。左から伸びる（2P は右から）
- 視界（640×480）の座標系で、キャラやステージの上に描く
- システムの画像にも、パレット（`palettes.png` の 0 行目）を当てる。
  名前の「ゆい and えこ」の、サポート名の画像（#242 など）が indexed のため。当てていなかった間は、名前が崩れて見えた
- 描く順番: ステージ奥 → キャラとオブジェクト → **ステージ手前** → システムの HUD → **キャラ側の HUD**（`picXY` のオブジェクト、`drawScreenObjects`）
  - 以前は `picXY` のオブジェクトを他のオブジェクトと一緒に描いていたため、ステージの手前の草花に隠れていた
  - 最後に回すのは、**キャラより手前（深さ > 80）の** `picXY` だけ。キャラより奥の `picXY` は、今までどおりキャラの奥に描く。
    例: 超必殺のカットインの背景 #3012（640×480、#788:23、深さ 68）はキャラの奥。
    全部を最後に回したら、この背景がキャラを覆い隠した

## 必殺ゲージのストック数

  位置は「位置：スペシャルストック 1P / 2P」（#74 / #75）の Settings: (12, 476) と (627, 476)
- エンジンは、ストック数 n の技 #(45 + n) をその位置で走らせる。n が変わったら出し直す（`src/hud.lh` の `step`）。
  画像は左上基準
- **表示は「ストック数 − 4」**。数字の画像（#262〜#269）は「-4」「-3」「-2」「-1」「0」「—1—」「2」「—3—」で、
  ストック 0 の技が「-4」を出す。ゆいは開始時 4 本 → 「0」（原作のスクショと一致）。最大 5 本 → 「1」、光る演出付き（#50）
  - 画像がばらばらに見えるのはこのため
- 原作は、必殺ゲージの隣に「Lv」なしでこの数字だけを出す（ユーザー確認）
- 1P の「—1—」（幅 169、x −84 から）は、左側の線が画面外に出る。原作でも両横の線は見えないので、これで正しい（ユーザー確認）

## タイマー

- システムの組み込み技 34 が「タイマー数字 ∞」、35〜44 が「タイマー数字 0〜9」。位置は「位置：タイマー」（#71）の Settings: (320, 65)、width 35 を**桁の間隔**と見た
- 十の位を x = 320 − 17.5、一の位を x = 320 + 17.5 に置き、その桁の数字が変わったら技を出し直す（`src/hud.lh` の `stepTimer`）。
  原作のスクショの「35」の位置とほぼ合う
- 数字の技は、データ変数 198（残り時間の秒）を見る。**8 秒未満だと、光って効果音 12 を鳴らす**（毎秒出し直すので、一の位が 1 秒ごとに鳴る）
- 時計は 100 フレーム = 1 秒。`main.lh` の `roundFrames` を毎フレーム減らし、`vp.fighter.setRound` でデータ変数に渡す
- **ラウンドの時間は 60 秒**（原作の EASY / NORMAL の画面で「60」から始まる）。データ（.kgt / .player / .demo / .stage）からは見つからなかった。
  `game.ini` の `Editor.TestPlay.time=60` はエディタのテストプレイ用の値
- **∞ が出ていた（修正済み）。** 出していたのはレイアウト 5（#61）。2 フレーム目に残り時間（データ変数 198）を読み、
  59 なら「60」の大きな画像（#320）、69 なら「70」、79 なら「80」、0 なら何も出さない。**それ以外なら ∞（#323）**を出す（時間無制限のモード用）
  - 原作の時計は 6000 から始まり、198 = 時計 / 100 は開始直後に 59 になる。移植は 6099 から始めていたので 60 になり、∞ が選ばれていた
  - → 時計を 5999 から始める。開始演出の間は時計を止め、数字を隠す（システム変数 128 = 10000）。
    開始演出の長さは仮に 660 フレーム（ラウンドの流れを作るまで）→ 0013 でラウンドの技に置き換え。
    数字の技は、1 ラウンド目は 670 フレームごとに 128 を見直すため、それより短くしている
  - 「60」の画像は、E で終わったら消す。生成器の `--layers`（ステージと同じく、E で終わる技の画像を消す）でシステムの技を生成する
- 数字の技は、**システム変数 128 が 9999 より大きい間は数字を画面外に出す**（隠す）。
  ラウンド開始の演出（#13 など）が 128 に 10000 を入れる → 原作は開始演出の間 タイマーを隠す／止める。移植はまだ演出を走らせていない
- 未実装: 時間切れの決着、開始演出が終わるまで時計を止めること
