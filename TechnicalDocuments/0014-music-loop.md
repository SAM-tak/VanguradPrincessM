# 0014: BGM のループ

- **日付**: 2026-09-29
- **状況**: ステージの音楽が 1 回で止まっていた（原作はループする）

## 調べたこと

- スクールの BGM は「すく.wav」（ステージの音 #1、22050 Hz ステレオ、95.85 秒）。ステージの #1（スクリプト1）が S ブロックで鳴らす
  （1 ラウンド目の開始時と、システム変数 139 が 0 に戻ったとき）。ステージの「BGM」設定は nosound.wav で使われていない
- **ループポイントはない**:
  - WAV に `smpl` チャンクがない
  - `iwep` / `iwem` チャンクは、波形編集ソフト「Sound it! 3.0」の編集情報（カーソル位置、マーカー 0 個）
- データ上もループの指定はない: 全キャラ・ステージ・システムの音の `endlessLoop` は偽、CDDA も使っていない
  → **誤り**: fm2ndparser の読み違い。下の「訂正」を参照
- 曲の作り: 先頭のサンプルからいきなり全音量で始まり、最後の約 1.5 秒でフェードアウトして無音で終わる
  （RMS: 95.0 秒 0.028、95.8 秒 0.002）。末尾は途中のどこともつながらない（相互相関 0.1）
  → **ファイル全体を頭から繰り返す単純ループ**の作り

## 決定

- ステージのスクリプトが鳴らす音はファイル全体でループ再生する（→ 訂正後は音ごとのループの旗に従う）
- 長いので `stream` で読む（キャラの効果音は今までどおり `static`）
- 同じ音を S で鳴らし直したら、頭から（今までどおり止めてから鳴らす）
- 原作のエンジンがどの条件でループさせているか（ステージの音だけか、長さか）は資料からは分からなかった。見つかったら合わせる

## 訂正: ループのフラグはデータにある（2026-09-29 追記）

- 音は、ファイルの中に **WAV のまま**入っている（種類は WAV / MIDI / CD トラック。このゲームは全部 WAV）。
  各音の見出しに 1 バイトの旗があり、下位 4 ビットが種類、**ビット 4（0x10）がループ**
  （wanwan の資料 `docs/editor/test_play_and_audio.md` §3.2 / §4.1: WAV なら `SND_LOOP` を付けて鳴らす）
- **fm2ndparser はループをビット 5 から読んでいた**ため、全部「ループしない」になっていた。直して読み直すと:
  - ループ: ステージの曲（すく、プール、和、よる、370-15、おかfff、00ラスト）、選択画面の曲（せれーん）、モード選択の曲、
    イベントの一部（らす、ネクスト、かぜ など）
  - ループしない: 選択画面の「0コイン」「コイン4」「決定」、タイトルの曲（はじまり）、エンディング、ジングル（かち など）
- → エンジンは音ごとに sounds.lton の `endlessLoop` を見る（`loops`）。キャラ・ステージ・デモ・システムの区別なし。
  ループする音はストリームで読む
- 途中で置いた「60 秒以上ならループ」という規則は取りやめた（原作がそういう規則のはずがない、というユーザーの指摘どおり）
- 場面（選択画面 ⇄ 試合）を切り替えるときは、鳴っている音をすべて止める（そのまま残す）

## 確認

- 再生中に 95 秒へ飛ばし、約 5 秒後も再生中で、ファイルの 4.5 秒目にいる（末尾から頭へ戻った）
