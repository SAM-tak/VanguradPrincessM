# CPU選択と入力履歴の原作準拠化

## 根拠と変更

原作実行ファイルの CPU 処理（0x411270）を調査し、Unicorn 上で実行した結果と照合した。

- 各登録に独立した確率判定を行い、距離・空中条件を満たした最後の登録を採用する。重み付き抽選を撤去。
- 難易度による選択待ち時間と各ステップの継続時間を原作の計算へ変更。無効ステップは終了として保持する。
- 技を直接開始せず、コマンド定義から入力履歴を生成して通常のコマンド判定と COM に渡す。連打・溜め・回転の展開と D 入力も対象。
- 独自の接近、ランダムガード、サポート専用待ち時間、近距離技選択、継続時間上限を撤去。
- 原作 CPU が参照しない continue フラグで入力を抑制しない。

`tools/fm2k_convert/cpu_data.py` は .player のコマンドと CPU 登録を読み、全100登録と入力履歴を生成する。`cpu.lton` と `story.lton` の出力は Windows でも LF に固定。

ゲームの乱数は LÖVE の乱数を15ビット範囲で使用する。原作全体の乱数列と同一になることを保証する変更ではない。入力履歴は既存 Fighter の方向表現に変換するため、逆方向同時押しの扱いまで原作 VM 全体との一致を検証したものではない。

## 検証

- `tools/probe-native-cpu.py`: 原作機械語によるコマンド入力生成と変換結果を2046条件で照合。
- `tests/cpu-native.lh`: 原作から採取した fixture と難易度0・20・60・100、距離・空中条件を変えた1600フレームを照合。
- `support-flow`: 全サポート、両 CPU 側の D 入力とゲージ消費を含め成功。
- `attract-flow`: 両 CPU の行動、タイトルとの往復、中断を含め成功。
- 生成済み CPU / story 全21ファイルに CR がないことを確認。
- ユーザーの CPU 戦テストで改善を確認。

既存 `story-flow` は CPU 戦まで進んだが、勝利を待つ phase 12 でタイムアウトした。テストの keypressed 呼び出しは実際の held 入力を再現しておらず、変更後の CPU に対する勝利確認は未完了。このテストを成功扱いにはしない。
