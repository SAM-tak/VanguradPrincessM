# 0013: ラウンドの流れ（VS 画面・READY / FIGHT・KO・勝ちマーク）

- **日付**: 2026-09-29
- **状態**: 1 ラウンド目の VS 画面 → 水玉のワイプ → 暗転 → フェードイン → READY → FIGHT → 対戦 → KO（PERFECT）→ 1P WIN →
  2 ラウンド目（READY 2 → FIGHT）まで、原作と同じ並びで動く。時間切れ・両者 KO・試合の決着は動かしていない（未確認）

## 仕組み（原作のデータから）

ラウンドの各段階は、システムファイルの組み込み技を**表示時間**（最初の Settings ブロックの time。2DFM_Player の `KgtShowTime`）だけ走らせる:

- start: #13 ラウンド開始時アニメ（2）
- call: #15〜#23 ラウンド 1〜9、#24 ファイナル（1 ラウンド目 425、以降 105）
  - **1 ラウンド目の VS 画面は #15 が出す**（#111:29 から、背景・枠・線・VS・名前・サポートの顔などを O で生成）。
    キャラの顔（カットイン）は、キャラの開始時技 #21 のオブジェクト
  - 原作の測定どおり、**VS 画面の裏でもう対戦（#21 の移動）が進んでいる** → 開始位置への移動は見えない
- ready: #25 READY … FIGHT（230）
- fight: 入力と時計が動く
- ko: #26 KO（100）、両者 KO は #33。勝った側の体力が満タンなら #27 PERFECT も出す。
  負けた側は**組み込みの「負け」#23**（KO で吹き飛んで倒れる技）へ
- win: 勝った側は組み込みの「勝ち」#22。#30 / #31「1P / 2P WIN」、引き分けは #32
- end: #14 ラウンド終了時アニメ（150）→ 次のラウンドの start。どちらかが 2 本取ったら、勝ち数を戻して最初から

表示時間は**次の段階へ進むまでの長さ**で、技そのものは自分で終わるまで走り続ける。
例: #25 はタイマーを隠すシステム変数 128 を、表示時間（230）より後に 0 へ戻す。表示時間で技を止めていた間は、タイマーの十の位が出なかった

勝ちマーク: #55 ON / #56 OFF を「位置：勝ちマーク 1P / 2P」（#76 / #77）の (264, 62) から左へ 20 ずつ、(372, 62) から右へ 20 ずつ、必要な勝ち数（2）だけ置く

## システムのオブジェクトの規則（VS 画面を合わせて分かったこと）

- **管理番号は使わない**（キャラとそのオブジェクトだけのもの）。
  #15 は VS 画面（#111:29）と #128 を同じ番号 0 で出す。置き換えると VS 画面が消えていた。
  wanwan の資料の O ブロック: サブオブジェクトでは管理の処理を飛ばす
- **O の位置は画面の座標**（生成元からのずれではない）。#122「ｖｓ」は (300, 320) にいて、文字を (300, 340) に出す
- **out / point のない O は、生成元の深さ**を受け継ぐ。VS 画面の名前（#119）と雪の飾り（#127）は、深さ 122 のサポート名（#120）が出し、
  深さ 105 の VS の枠より手前に見える
- 深さの大きいものが手前。システムの技そのものは 125、勝ちマークと HUD は 100。
  画面の座標の描画は、HUD、キャラの画面のオブジェクト（深さ 80 より手前）、ラウンドのものをまとめて深さ順に描く

## 実装

- `src/round.lh`: 段階の進行（`step`）、描くものの一覧（`items` と `byDepth`）
- `src/fighter.lh`: `system`（システムファイルのものか）。`spawn` が上の規則に従う
- `src/script.lh`: `showTime`。変換（`gen_script.py`）は Settings に time も書くようにした
- `main.lh`: 入力と時計は fight の間だけ。ラウンドごとに位置・体力・オブジェクト（弾・設置物・サポートも）を戻して #21 から（`startRound`）。
  **キャラ変数（64〜79）とタスク変数、DS の登録も消す**。
  残していた間、2 ラウンド目のサポートキャラ（キャラ変数 73〜77 などで動く）が、前のラウンドの勝ち・負けポーズのまま手前で固まっていた。
  **1 回の描画で進めるのは最大 2 フレーム**にした。最初の数秒は画像の読み込みで描画が止まり、その間にゲームだけが最大 10 フレームずつ進んで、VS 画面を見せずに過ぎていたため
- デバッグ: K で練習相手の体力を 1 にする（次の一撃で KO）
- 0010 の仮の「開始演出 660 フレーム」は廃止。タイマーを隠すのも止めるのも、ラウンドの技と「fight の間だけ時計を進める」で決まる

## ヒットストップ = PS はその場で止める命令（2026-09-29）

- **PS は「自分を yourTime、相手（とそのオブジェクト）を hisTime フレーム、その場で止める」**。
  出典: wanwan の逆コンパイル資料（opcode_dispatcher.md の `[PS]`）。オブジェクトが実行した PS は何もしない
- それまでは「次に当たったときのヒットストップ」の予約として扱っていた（0008 の記述）。これが誤りだった。
  PS は、やられ技の中や技の開始時に置かれている:
  - やられ「ヒット超」#135: `PS 自分 0 / 相手 16`。攻撃側だけが 16 フレーム止まり、やられ側はその間に打ち上がる（その後 M で上へ）
  - きりもみ #153: `相手 18`
  - 超必殺「ちょっぴ」#292: 技の開始時に `相手 110`。暗転演出の間、相手が止まる
- 結果: 超必殺の切り上げの初段で強いヒットストップがかかり、その間に打ち上げやられが見える。次の一撃で空中からきりもみになり、
  約 74 px 浮いて回り、約 0.9 秒で着地してダウン（ユーザーが示した原作の動画のとおりの流れ）。
  それまでは打ち上げが起きず、地上からきりもみを始めていたため、34 px ほどしか浮かなかった
- 止まっている間も、始まったばかりの技の最初のコマだけは出す（やられの絵がすぐ出る）。待ちは停止の後から数える
- 停止中に新しい PS が来たら上書き（格闘ゲームの一般的な作り。ユーザーの判断）
- 途中で試して捨てた扱い: 「技を始めたら PS を 0 に戻す」「PS は当たった一撃で使い切る」。どちらも予約という誤った前提の上の修正だった
