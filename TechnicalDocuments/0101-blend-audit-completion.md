# 合成描画の照合と0074の対象範囲の完了

2026-10-08。合成描画の実装変更は不要と確認した。テストと監査記録を追加する。

## 原作との対応

原作EXEの0x40C282はCOLORのmodeを読み、0x40C840の分岐表で5方式を選ぶ。

| mode | 原作の処理 | フルカラー版の対応 |
| --- | --- | --- |
| 0 | 0x40C29B、非透明の色を上書き | alpha合成、不透明度1 |
| 1 | 0x40C2E4、背景と描画色を半分ずつ加算 | alpha合成、不透明度0.5 |
| 2 | 0x40C3AE、チャンネルごとの飽和加算 | add |
| 3 | 0x40C4E5、背景から描画色を減算し下限で制限 | subtract |
| 4 | 0x40C648、背景係数a、描画色係数32-aを使い32で除算 | alpha合成、不透明度(32-a)/32 |

原作0x40D5B5以降は元の純黒を透明として除外し、その他のパレット色を5bit化してCOLORの符号付きRGB補正を加え、0～31に制限する。0x40D634付近では補正後の黒が透明キーにならないよう非ゼロ色を残す。

現行は変換済みalphaで透過を保持し、パレット参照後にRGB補正・clampを行い、その結果を合成する。RGBを黒く補正してもalphaは消えず、逆に透明画素へ明るい補正を加えても不透明にはならない。

原作の16bit格納、5bitへの切り捨て、半透明時のビットマスク、減算の低位ビット制限、透明キー回避用の最低色をピクセル単位で再現するものではない。ユーザーが了承したフルカラー維持の方針に従う。現在のRGB補正単位は1/32で維持し、原作スクリーンショットと完全一致したとは主張しない。

## GPU実測

`tests/sprite-blend.lh`と小さな画像形式メタデータfixtureを追加。画像・パレットはテスト内で生成し、実際のSheet.draw、sprite shader、setBlend、Fighter.colorを使ってCanvasへ描く。Canvasの画素を読み戻して合成式と比較する。

- indexed/RGBAの2経路。indexedはパレットの第3行を参照。
- 5合成方式×透明度0/10/32×RGB補正0/+16/-16、計90描画。
- 各描画で不透明・完全透明・中間alphaの3画素を検証。
- 加算上限・減算下限、補正のclamp、透明度端点を含む。
- 許容誤差は8bit換算で2階調。原作の低ビット色演算ではなく、維持するフルカラー合成式が参照値。

`build/sprite-blend-audit.log`: PASS。テスト以外の描画コードは変更していない。
