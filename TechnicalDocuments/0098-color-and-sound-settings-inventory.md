# COLORと音声設定の使用範囲

2026-10-08。0074の残件を、命令のオペランドと実際の描画・再生経路に分けて確認する。今回は棚卸しと原作のCOLOR命令処理の照合。ゲーム本体の動作変更はない。

## COLORの透明度フラグ

原作EXEのopcode 35の移譲先は0x413A07。

- 0x413A07–0x413A21でRGBを符号付き8bit、合成モードを符号なし8bitとして読み出す。
- 0x413A24でモード4かどうかを比較する。4なら0x413A2Aでalphaを符号付き8bitとして読む。それ以外は0x413A3Dでalphaを0にする。
- パーサーJSONの`aEnabled`を独立した実行フラグとして読む処理はここにはない。現在の変換器がこの値を省略し、モード4だけで透明度を選ぶことは適切。

更新版10キャラのJSONでも、`aEnabled=true`はモード4の8,796件のみ。falseはモード0:7,508件、1:18件、2:9,304件、3:1,276件。これは全デモ・全ステージの生データ検証ではない。

生成済みdata全体（`_conversion`を除外）のCOLORは40,242件。

| モード | 定義数 |
| --- | ---: |
| 0 | 9,867 |
| 1 | 19 |
| 2 | 12,453 |
| 3 | 2,612 |
| 4 | 15,291 |

RGBは符号付きで-32～32、alphaは0～32の範囲内。現在の`tintOf`の範囲制限や、`Fighter.color`のalpha非負制限によってVPの指定が失われる例はない。原作が符号付きで読むalphaも、現行データはすべて非負なので解釈の差は出ない。

これは命令の状態設定と入力範囲の確認。原作の整数色演算とシェーダーの最終ピクセル値の一致を実証したものではない。レイヤーのスクロール・連結も今回の確認対象ではない。

## 音声メタデータ

data配下のsounds.ltonで確認した定義（参照・到達可能性ではなく保存数）:

- type=0 / 非ループ / CDDAトラック0:36件。
- type=1 / 非ループ / CDDAトラック0:1,295件。
- type=1 / ループ / CDDAトラック0:15件。

現行データでCDDA等の別種音源を実装する必要はない。WAVの通常再生とループ指定には既存のSource生成・setLooping経路がある。ただし、同じ音の連続再生、停止、所有者やシーン間の扱いが原作と一致するかは、このメタデータだけでは判断しない。

## 再検査と残件

`audit_vm.py`に`render_sound_inventory`を追加。合成モード、RGBA値の分布、任意入力JSONのaEnabled分布、音声設定を出力する。COLORが確認範囲外、または音声に別種設定が追加された場合はfindingsにも記録する。

実行: `python tools/fm2k_convert/audit_vm.py --json-dir build/update-0117/new-json`

残件は実際の合成描画・レイヤー挙動・音声再生経路の照合。未使用の一般的なFM2K機能へ対象を広げない。
