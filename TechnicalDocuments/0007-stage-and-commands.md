## ステージ

- **ステージのスクリプト 1 つ = レイヤー 1 枚。** キャラの技と同じブロック（I / M / V / COLOR / S / SG）で動く。
  → 同じ生成器で L^ にする: `gen_skills.py <json> school --stage` → `src/stages/school/`
- レイヤーの先頭の Settings（settingsType 6）が、横・縦の**スクロール率（%）**と**ループ**を持つ
  （`widthEnabled` / `heightEnabled` が無ければその向きはスクロールしない = 画面に固定）
- **ステージの画像は左上基準**で置く（キャラは下端中央。0002）
- スクリプトの番号順に奥から描く。**「プレーヤー位置」という名前のスクリプト**の位置にキャラを描く（スクールでは 14 枚中 10 枚目の後）
- ステージの大きさは 1280×960 固定
- スクロール: スクロール率 s のレイヤーは、カメラが 1px 動くと s px 動く。
  **カメラがステージの左上にあるとき、スクリプトの指定どおりの位置に来る**（2DFM_Player と同じ）。
  根拠: スクールの前景（#12）は幅 1388 = 1280 + 640×0.16（スクロール率 116%）、
  縦は y = 789 で高さ 267、カメラが下端のとき 480×0.2 = 96 上がってちょうど 960 で終わる。この基準でしか辻褄が合わない。
  （最初は「視界の中央・下端が基準」と置いていたため、左端で前景の端が見えていた）
- ループするレイヤーは、視界を覆うまで並べる
- 実装: `src/stage.lh`（レイヤーは Fighter を流用。地面に着かないよう ground を遠くに置く）

## 透過色の訂正（0002・0003 の「番号 0 が透明」は誤り）

- FM2K の透過は**純黒 RGB (0, 0, 0)**。絵の中の黒は (8, 0, 0) のような「ほぼ黒」で描かれている
- キャラの共通パレットでは純黒が番号 0 なので、キャラだけ見ていると「番号 0 = 透明」に見えていた。
  ステージの画像は純黒が番号 3・16・25 などにあり、背景が黒い四角で表示されていた
- 変換器（`convert.py` の `palette_rgba`）を「純黒なら透明」に直して、全画像を変換し直した

## COLOR（合成方法）

2DFM_Player に合わせた:

- 0 通常 / 1 半透明（50%）/ 2 加算 / 3 減算 / 4 不透明度 = (32 − a) / 32
- RGB の色付けはまだしていない

## コマンド

- キャラのコマンド表（`.player` の 82 バイト × 最大 100 件）を、生成器が `install` の中に `addCommand(...)` として書き出す
- 1 件 = 入力の手順（方向コード＋ボタン、最大 10 段）、受付時間、状態別の技番号（空中 / 立ち / 遠立ち / しゃがみ）
- **通常攻撃（A = #213 など）やジャンプ（↑ = #4）もコマンド表にある。** 手で書いた割り当ては不要になった
- 表の順が優先順（必殺技が先、通常技が後）
- 方向コード: 0 どれでも / 1 ニュートラル / 2 前 / 3 前下 / 4 下 / 5 後下 / 6 後 / 7 後上 / 8 上 / 9 前上 /
  10〜13 その側の 3 方向（後 / 上 / 前 / 下）。例: 昇竜 = {2, 4, 3}+C（→↓↘C）
- 照合: 直近 64 フレームの入力（向き基準のテンキー方向、そのフレームに押されたボタン）を新しい方から見て、
  最後の段が**このフレーム**、残りの段が受付時間内に順に見つかれば成立
- キーボード: Z X C A S D = ボタン A〜F
- 確認済み: 236+A → #269、623+C → #265（続く #298 も）、214+B → #276、66 → ラン（#32 → #33 → #34）

## キャンセル（C ブロック）

- C は「今のキャンセル条件」を置き換える（最後に実行したものが有効）。入力が来たときに参照する
- **Fail = キャンセル不可**、**Hit = 攻撃が当たった後**、**Uncond = いつでも**。
  対象は「技番号 1 つ」または「レベル from〜to の技」
- 技のレベル（Settings の level）: 基本動作 0、通常技 48〜80、必殺技 90〜120（ゆい）
- レベル 0 の技（立ち・歩き・しゃがみ・ジャンプなど）からは、いつでも別の技を始められる
- FA の `cancel` フラグ（「当たった後キャンセル可能」）: **当たった後、今よりレベルの高い技へ**とした。仮定
- ゆいの通常技は、到達できる経路に C Hit を持たない（`C fails 0 0` だけ）。原作で通常技から必殺技へキャンセルできるなら、
  別の仕組み（システム変数 138 など）を探す必要がある

## ヒット判定（最小限）

- 攻撃判定（FA）が相手のやられ判定（FD、押し合い専用以外）に重なったら「当たった」とする
- 当たった側だけ処理: C Hit の窓が開く、DS「attacking」が発火する。**相手はまだ反応しない**（R の反応、ダメージ、のけぞりは未実装）
- 確認: 弱キックは相手との距離 100〜160px なら 9 フレーム目に当たり、260px では当たらない

## lhat について分かったこと

- 多値を返す呼び出しをそのまま `return^` すると、型検査は通るのに実行時に誤り
  （`this call and what it called disagree on how many values come back`）。いったん `let^ w, h = …` で受けてから返すと通る
  → **lhat 側で修正済み**。`Sheet.size` は直接 `return^tex.getDimensions()` に戻した
- **後ろで定義される名前を参照すると、無関係な誤りになる**（0006 のメソッドと同じ。モジュールの変数でも起きる）。
  「this name is already defined in this scope: fighter / sprite」「this name is read before its let^ has run」
  → **lhat 側で修正済み**（2026-09-28 18:00 ビルドで確認）
- `let^` で別名にした定義（`let^Fighter = vp.fighter.Fighter`）を `fits^` に使うと、実行時に一致しないらしい。
  注釈（`p^me:Fighter`）では問題なく使える。配列は `for^k, l in^ 配列` で回せば絞り込み不要
  → **lhat 側で修正済み**（2026-09-28 のビルドで確認。`src/hud.lh` を `fits^Fighter` に戻し、ゲージが描かれる）

## 技の終わりの切り替え

- 地上で技が終わったら、**そのフレームの入力で次の技を選ぶ**。いったん立ちを挟むと、歩きの折り返しで立ちのコマが 1 フレーム見えていた
- しゃがみの技（コマンド表でしゃがみ専用の技）が ↓ を押したまま終われば、しゃがみ込みを経ずにしゃがみへ戻る

## レイヤーの終わり方: E と「最後まで行く」（2026-09-28）

- **E（終了）で終わるレイヤーは消える。最後のブロックを過ぎて終わるレイヤーは、最後の画像を出し続ける**
  - 後者の例: スクール #13（画像 #58 を 2 フレーム出して終わる。以後もずっと見えている）
  - 前者の例: スクール #14。1 ラウンド目の開始演出で、背景全体（画像 #0、1280×960）の複製を画面に固定して出す。
    白から戻る色で、毎フレーム 0.6 px ずつ上がり、E で終わる
- 以前は両方を同じ扱い（最後の画像を残す）にしていた。ラウンド数（データ変数 199）を返すようにしたら、#14 の演出が走るようになった。
  その結果、複製が上へ動き続け、画面上部に継ぎ目（地面の上に空）が見えた
- 生成器: `--stage` のときだけ、E を `vanish(me)`（`alive := false^`）+ `return^` にする。`src/stage.lh` は `alive` でないレイヤーを描かない
