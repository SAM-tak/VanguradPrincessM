# DS発火元の実装と残る再現差の区別

追記：ここで挙げた残件は [0083](0083-remaining-event-paths.md) で実装・検証した。以下は実装前の監査記録。

2026-10-07。0081の「6種類に発火元が揃った」は、全イベントの全経路・順序が一致したという意味ではない。ユーザーからの確認を受けた追加監査。今回はコード変更なし。

## landing: 専用遷移が未分離

原作 `0x41241C–4124AE` は地面以上かつ下向き速度正の着地を検出し、位置・運動を止める。landingの登録だけを消費し、待ち時間を0にして `0x40E550` でFA/FDを消す。

一般の予約DS遷移 `0x412327–41238B` と違い、この経路では全DS登録を消す `0x40E510` やRを消す `0x40E540` を呼ばない。現在はlandingも `fire → dispatch` を使うため、他のイベント登録とキャンセル設定まで一律にクリアする。この差の修正・実データ影響検証が必要。

接地条件と速度停止、判定残留の解消には既存テストがあるが、それで着地遷移全体の一致を証明したことにはならない。別経路 `0x411867` には被弾状態ビットの変更もあり、状態別の確認が必要。

## attacking: 命中経路と処理順の残件

0081で本体の命中イベント確定、相打ち抑制、既存DS優先、生成物自身への通知を追加した。ただしゲーム全体の命中対象は今も相手本体中心で、原作 `0x40F36A` にある生成オブジェクトへの命中からattackingを発火する経路は網羅していない。

また現 `stepFighters` は両者のstep（移動・着地・壁・スクリプト）を先に行ってから相殺・命中・押し合いへ進む。原作 `0x40FFC0` 内は相殺・命中・移動処理・本体命中イベント確定の順。同フレーム内の全体スケジュールまで一致したとはいえない。

## defending: 相殺側の別経路が未実装

通常の「自分の攻撃がガードされた」際に攻撃者へ発火する経路は照合済み。

一方 `0x40EF33–40EF99` では、FA同士の衝突について威力0と属性ビット（FA+0x0Bの0x80）の条件を調べ、生成物の `+0x68`（defending）へ通知する別経路がある。現 `offsetAgainst` はoffsetWayとFA配列消去だけを扱い、この経路を実装していない。該当属性と原作側の消去処理の意味を確定してから実装する必要がある。

## wallHitting: 基本経路はあるが順序・境界条件の照合が残る

壁のクランプ、イベント発火、DS遷移初期化、左右の壁反動は実装・回帰テスト済み。

原作 `0x40FAC3` 以降はwallHitting登録の有無でも境界処理の経路を切り替える。現在は `confineMotion` で統一的にクランプして通知する。画面端とステージ端の選択、および同フレームの命中・着地との処理順を含めた全面照合は未完。これは今回新たに実害まで再現した不具合という意味ではなく、完全一致を未確認の範囲。
